# Blackout Freight · технологии и инженерные решения

Blackout Freight — кооперативная игра Roblox для 1–4 игроков. Технический кейс охватывает путь от стрелки над HUD до решения о раскатке. Игровой сервер определяет, кто участвует в эксперименте, а инструмент на Python помогает разработчику проверить, какой вывод допускают собранные данные. [Видео игры](../dist/blackout-freight-v24-demo.mp4) · [Закрытый релиз и QA](portfolio-release-2026-11-16.md)

## Что делает облачный агент

Агент получает результаты расчёта по зафиксированной таблице демонстрационных данных. В контексте есть источник, изменение доли доставок и защитная метрика захватов. Индивидуальные записи игроков в бриф не попадают. Модели могут предложить публикацию результата симуляции, рекомендацию раскатки или заявление о наблюдаемом эффекте у игроков. MCP-инструмент заново вычисляет допустимое решение из исходного CSV. Попытку приписать симуляции эффект в живой игре он отклоняет. [Адаптер агента](../analysis/agent_review.py) · [Расчёт решения](../analysis/compass_report.py) · [Данные](../analysis/synthetic_compass_counts.csv) · [Skill аналитика](../.agents/skills/freight-experiment/SKILL.md)

На собеседовании по **Game AI Engineer** можно показать путь от действия игрока до серверного события. Для **Cross-product** — как правило о происхождении данных превращается в проверку для любого клиента MCP. Для **Platform** — почему два экземпляра сервиса возвращают одинаковый вердикт и почему другая команда делает собственный запрос к модели. Удержание и реальный прирост доставок требуют отдельного пользовательского исследования.

## Инфраструктура, доступ и наблюдаемость

Две реплики Python/FastAPI работают в Kubernetes (kind) на стандартном Ubuntu-раннере GitHub Actions. На этом же раннере llama.cpp обслуживает два отдельных CPU-маршрута — Qwen2.5-0.5B-Instruct и SmolLM2-360M-Instruct. Шлюз направляет запрос на выбранную модель, а отдельный процесс игры обслуживает MCP по stdio. Код платформы общий для трёх игр. В каждом репозитории есть собственный MCP-адаптер и workflow. [Workflow этой игры](../.github/workflows/game-agents.yml) · [Шлюз на проверенной ревизии](https://github.com/GlebAvershin/lantern-atlas/blob/4103603adde3dd325d511a2a2df66db834757f13/studio/agents/gateway.py) · [Kubernetes-манифест](https://github.com/GlebAvershin/lantern-atlas/blob/4103603adde3dd325d511a2a2df66db834757f13/studio/agents/deployment.yaml)

- **Контекст и качество.** При запуске реплика читает ресурс с брифом игры. Для задания допускается до четырёх вариантов, размер сериализованного брифа ограничен 8 КиБ. Вывод модели ограничен JSON-схемой. Принятие решения принадлежит игровому инструменту. При отказе агент передаёт причину модели и исключает этот вариант из следующей попытки. [Контракт проекта](../analysis/agent_review.py)
- **Параллельные запросы и кеш.** В ключ входят игра, команда, ревизии игры и платформы, модель и отпечаток её весов, промпт и бриф. Транзакционная advisory-блокировка PostgreSQL 16 координирует запросы на разных репликах. Принимается только проверенный результат, срок действия — сутки. Ошибка до фиксации освобождает блокировку. Две тестовые команды используют отдельные bearer-токены. Запрос с неверным токеном получил 401.
- **Ревью и диагностика.** Ресурс MCP предоставляет информацию GitHub Actions о PR и ограниченный фрагмент кода из проверяемого git-коммита. Второй ресурс отдаёт записи SDK Sentry и Amplitude с локального приёмника на раннере. На контролируемый отказ записывается одно сообщение, на принятые решения — два события. Qwen получает фрагмент кода и отрицательный контроль и предлагает дополнительный тест. Qwen предложил проверить некорректный вход функции brief. У объявленного MCP-ресурса нет пользовательских аргументов. Для этого сценария существеннее тест недопустимого вывода на корректном наборе данных. [Реализация](https://github.com/GlebAvershin/lantern-atlas/blob/4103603adde3dd325d511a2a2df66db834757f13/studio/agents/release_review.py) · [Ответ модели и данные SDK](evidence/cloud-review.json)

## Измеренный результат

Qwen сначала предложил раскатить компас. Инструмент вернул simulation_only. В следующем запросе агент добавил вердикт в контекст, убрал отклонённый вариант и получил допустимый ответ. SmolLM2 выбрала отчёт о симуляции с первой попытки. Поэтому на два готовых результата пришлось три вызова LLM. [Исходные запросы и ответы](evidence/cloud-review.json) · [Публичный прогон](https://github.com/GlebAvershin/blackout-freight/actions/runs/44771405268)

| Серия одной тестовой команды | Клиентские запросы | Вызовы LLM | Токены inference | p95 у клиента |
| --- | ---: | ---: | ---: | ---: |
| Пустой кеш, обе модели уже загружены | 8 | 3 | 873 | 2614,54 мс |
| Повтор | 8 | 0 | 0 | 31,24 мс |
| После замены обоих pod | 8 | 0 | 0 | 38,49 мс |

В каждой серии четыре запроса направлены к каждой модели, трафик разделён между двумя репликами. В первой серии шесть запросов переиспользовали результаты соседних запросов. Та же задача для второй команды дала отдельный промах. После rolling restart проверены новые имена обоих pod и сохранность результатов для каждой команды. Таблица включает токены всех попыток **первой команды** для игрового задания. Отдельный обзор PR, контрольный запрос второй команды и подготовка инфраструктуры в неё не входят. На восьми запросах p95 по методу ближайшего ранга совпадает с максимумом. Это короткий функциональный нагрузочный тест.

**Как повторить.** В разделе Actions этого репозитория выбрать *Game review agents → Run workflow → main*. Стандартный раннер поднимет временный кластер и PostgreSQL, загрузит веса с проверкой SHA-256 и сохранит артефакт `game-agent-evidence`. В нём есть ответы до и после перезапуска, события SDK и текст ревью. Прогон работает также при открытии PR. Постоянный сервис и платный аккаунт модели для проверки не требуются. [Сценарий нагрузки](https://github.com/GlebAvershin/lantern-atlas/blob/4103603adde3dd325d511a2a2df66db834757f13/studio/agents/probe.py) · [Запуск и остановка кластера](https://github.com/GlebAvershin/lantern-atlas/blob/4103603adde3dd325d511a2a2df66db834757f13/studio/agents/cloud.sh)

**Связь с вакансиями.** Практический опыт этого проекта охватывает инструменты для игровой команды, контекст MCP, маршрутизацию LLM, учёт времени и токенов, кеш и облачное выполнение. Конкретная среда измерений — GitHub Actions и открытые веса. Amazon Bedrock, Databricks AI Gateway и коммерческие модели перечислены в стеке Playrix. Боевые аккаунты этих сервисов и внешние аккаунты Sentry/Amplitude в данном прогоне не использовались. Источник требований — три карточки вакансий, сверенные 20 ноября 2026 года. ## Проверка через подписки разработчика

Каждая модель определила, какой вывод допустим по синтетическим данным компаса. Валидатор заново вычислил решение из CSV и проверил источник данных. Один и тот же MCP-бриф передан Codex CLI через вход ChatGPT и Gemini через Google Antigravity CLI. Обе команды запущены на Mac. Инференс выполняли сервисы провайдеров.

| Маршрут | Запрошенная модель | Выбор | Вердикт игрового инструмента |
| --- | --- | --- | --- |
| Codex | gpt-6.2-sol | `report_simulation` | Принято |
| Google Antigravity | gemini-3.8-flash-low | `report_simulation` | Принято |

В протоколе сохранены обоснования моделей, версия исходников, хеш брифа и независимые вердикты. Это по одному завершённому решению на маршрут. Скрипт использует локальные сеансы CLI, для Gemini отключает расход дополнительных AI-кредитов и передаёт ответы существующему MCP-инструменту. Облачный нагрузочный тест выше использует отдельные серверы Qwen и SmolLM2. [Протокол](evidence/subscription-review.json) · [Скрипт](https://github.com/GlebAvershin/lantern-atlas/blob/main/studio/agents/subscription_review.py) · [Вход ChatGPT](https://learn.chatgpt.com/docs/auth) · [Вход Google](https://antigravity.google/docs/install)

Для повторения из корня этого репозитория используйте Python-окружение проекта Lantern Atlas (`uv sync --project studio --locked --python 3.12` из его корня). Для Blackout Freight также выполните `uv sync --project analysis --locked --python 3.12`. После входа в официальные CLI выполните:

```sh
platform="../Lantern Atlas"
"$platform/studio/.venv/bin/python" "$platform/studio/agents/subscription_review.py" --game freight --game-root . --provider codex
"$platform/studio/.venv/bin/python" "$platform/studio/agents/subscription_review.py" --game freight --game-root . --provider gemini
```
